# 时令美食地图 · 架构与决策记录

## 1. 数据模型

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| stalls | id, name, region, lng, lat, version | 摊位是身份主体；坐标只是属性，同坐标多摊不合并 |
| ingredients | id, name | 食材 |
| seasons | ingredient_id, region, intervals[], effective_from/to, source_date | 时令按**地区**分别维护；区间 `{start:{m,d}, end:{m,d}}`，起点晚于终点即**跨年**（如 11-01 至 02-28） |
| offerings | stall_id, ingredient_id | 摊位供应关系 |
| hours | stall_id, weekday, segments[{open,close}] | `close <= open` 视为**跨午夜**，段归属开始当日 |
| closures | stall_id, effective_from/to, source_date, announced_at | 临时停业按**生效范围**生效；`announced_at`（正式公告）仅作来源信息，可晚于生效起点 |
| queue | stall_id, minutes, collected_at | 易失运营数据，直写线上；超过 15 分钟即为过期 |

每次写操作都把**来源日期（source_date）与生效范围（effective_from/to）**写入数据库；
编辑走乐观锁（`base_version`），冲突返回 409 与当前版本。

## 2. 可购买性语义

- **季节性供应**（in_season_now）：按摊位所在地区的时令区间 + 行生效范围判断；
- **当天实际营业**（open_now）：按营业段（支持跨午夜）判断，且当前时刻不在任何临时停业的生效范围内；
- **可购买**（available_now）= 应季 ∧ 营业。
  月份筛选只是浏览粗筛（区间与月份有交集即命中），**不能由单一月份字段推断都可购买**——
  例如全年应季的米皮店凌晨不营业，10 月 31 日深夜羊肉摊在营业但尚未应季。

## 3. 索引方案：预计算时空索引 vs 查询时求交

| 维度 | 全预计算时空索引 | 全查询时求交 | **本方案：分层混合（已采用）** |
| --- | --- | --- | --- |
| 预计算内容 | 空间网格 + 月份×食材 + 时刻营业状态 | 无 | 空间网格 + 月份×食材应季集合 |
| 查询时计算 | 仅查表 | 空间扫描 + 时令 + 营业段 + 停业全部现算 | 营业段（跨午夜）、临时停业、精确日期边缘按请求时刻求交 |
| 更新及时性 | 数据编辑要重建；**时刻状态每分钟都在变，预计算必然过期**（要么每分钟重建，要么展示过期“营业中”） | 任何时刻都新鲜 | 数据类变化随发布同代生效；时钟类状态零延迟，永远按当前时刻计算 |
| 写成本 | 每次发布 O(摊位×12月×供应) + 若含时刻状态需周期性全量重建 | 零 | 发布时一次 O(摊位×12月×供应)，量级很小（演示数据 <1ms） |
| 读成本 | O(1) 查表 | 每请求 O(全部摊位) | O(网格单元 + 候选数)，瓦片/列表共享 |
| 存储 | 网格 + 月表 + 时刻桶，随时间粒度膨胀 | 无 | 网格 + 12×食材 集合，有界 |

**决策理由**：状态的变化来源有两种——**数据变化**（编辑发布）与**时钟变化**（时间流逝）。
把时钟驱动的状态（跨午夜营业、停业生效）塞进预计算索引，要么每分钟重建（成本不可接受），
要么接受过期结果（正确性不可接受，直接违反“区分季节性供应与当天实际营业”）。
因此：数据驱动的部分（空间、月份×食材）预计算、随发布重建；时钟驱动的部分查询时求交。
发布重建成本有界且低频，查询热点（地图瓦片）仍走预计算集合，兼顾及时性与成本。

## 4. 发布与同代切换

- 编辑写入 **drafts**，访客不可见；`POST /api/admin/publish` 把草稿整体晋升为 live 且 `gen+1`，
  随后立即用同一快照重建索引——**索引、卡片、地图三类读取共享同一 gen**，不存在半新半旧。
- 所有公共响应带 `gen` 与 `X-Data-Gen` 头；请求可携带 `gen`，
  若与当前代不一致则响应 `stale:true`（**旧筛选请求晚到**），客户端 `ClientCore.shouldAccept` 丢弃并按新代重取。

## 5. 地图聚合与降级

- 瓦片聚合按**摊位身份（stall_id）去重**计数；同坐标多摊保留各自 id 并列展示，绝不合并为同一商户。
- 瓦片端点失败（503）时，客户端按 `ClientCore.markerPlan` 降级为直接调用 `/api/stalls` 渲染点位，并提示用户。

## 6. 其他约束

- **过期排队信息**：卡片返回 `collected_at` 与 `stale` 标记，前端只展示“采集于 HH:mm（可能已过时）”，不当作实时事实。
- **离线包**：`/api/offline-pack` 注明 `valid.from/to`（覆盖区域与月份）与数据代，时效信息以线上为准。
- **路线**：`/api/route` 只作资料参考（`reference_only:true`），不自动给出食品安全或营养结论。
- 时区固定 +08:00 计算墙钟，避免服务器时区影响跨午夜与月底判断。
