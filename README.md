# 时令美食 · 数据编辑与查询服务

把原“时令美食地图”从静态展示改造为**数据编辑与查询服务**：后台维护食材季节窗口、摊位身份与位置、营业段、临时停业与排队采集；公开 API 与访客页面提供带时间语义的查询；后台发布以“代际”方式让索引、卡片、地图同代切换。

旧的西安文化静态站保留在 `/legacy/`（线上路径 `http://localhost:3000/legacy/index.html`）。

## 快速开始

```bash
npm start            # 默认 http://localhost:3000
ADMIN_TOKEN=xxx PORT=8080 npm start
npm test             # 47 项自动化断言（领域语义 + HTTP 端到端）
```

- 访客端（地图+列表共享筛选）：http://localhost:3000/
- 后台编辑与发布：http://localhost:3000/admin （开发令牌 `dev-token`，页面右上角可填）

## 核心规则（防误解）

1. **时令 = 显式窗口**：`(region, 起月日, 止月日, crossYear)`，可跨年、可按地区不同；**没有单月份字段，也不允许由月份推断“都可买”**。
2. **在季 ≠ 营业**：在季食材只说明时令；摊位是否开门由当天营业段（可跨午夜）与临时停业实时求值，两者分别返回。
3. **临时停业按生效范围生效**：即使“正式公告时间”在未来，只要编辑写入了已开始的生效范围，访客端立刻显示停业；可撤销。
4. **排队是采集快照**：带 `collectedAt/ttlMinutes`；过期后只显示采集时间并标注“非实时事实”。
5. **聚合按摊位身份去重**：同坐标的多个摊位各自计数、各自标点，不合并为同一商户。
6. **发布同代切换**：编辑先进草稿；发布冻结不可变代际，API/统计/瓦片（ETag）立即统一切换。
7. 路线仅资料参考；**不自动给出食品安全或营养结论**。

## 主要 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/stalls?at&region&ingredient&inSeason=1&open=1&q&bbox` | 地图与列表共享的查询 |
| GET | `/api/stats` | 同筛选的聚合（按摊位 id 去重） |
| GET | `/api/tiles/{z}/{x}/{y}.svg` | 瓦片；`?fail=1` 模拟瓦片失败 |
| GET | `/api/offline/manifest` `/api/offline/bundle` | 离线包与有效范围 |
| POST/PUT/DELETE | `/api/admin/ingredients`、`/api/admin/stalls`、`/api/admin/queues` | 草稿编辑（需令牌；摊位更新需 version 乐观锁） |
| POST | `/api/admin/stalls/{id}/closures` | 临时停业（可早于公告） |
| POST | `/api/admin/publish` | 发布新一代 |
| GET | `/api/admin/edits` | 编辑日志（含 409 冲突记录） |

## 手动验收脚本（对应验收清单）

- **月底切换**：访客端“评估时间”分别选 2026-10-31 12:00 与 2026-11-01 12:00，筛“周边区县 + 凉皮 + 仅在季”，可见 10-31 在、11-01 不在。
- **临时停业早于正式公告**：后台给 S004 加停业 `2026-10-07~2026-10-07`、公告时间填明天，发布后当晚即显示停业。
- **两编辑更正同一地点**：两个标签页同时编辑 S001，第二个保存收到 409 并可载入最新版本合并。
- **瓦片失败**：瓦片 URL 加 `?fail=1` 可验证 503；页面上失败时自动降级为纯标记视图。
- **旧筛选晚到**：勾选“模拟旧筛选请求晚到”后立刻改筛选再应用，旧结果在控制台打印“丢弃”，界面以新条件为准。
